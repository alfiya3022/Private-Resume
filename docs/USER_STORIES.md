# PrivateResume - User Stories and Acceptance Criteria

## Epic: Resume Management

### US-01 Upload master resume
As a candidate, I want to upload my master resume as a PDF so that PrivateResume can use it as the source document.

Acceptance criteria:
- Only supported PDF input is accepted in V1.
- Invalid files are rejected with a clear message.
- File metadata is persisted.
- The original source file remains available.

### US-02 Review extracted data
As a candidate, I want to review and correct parsed profile data before it becomes my structured source of truth.

Acceptance criteria:
- Extracted fields are displayed by profile section.
- Candidate can edit fields.
- Candidate explicitly saves corrections.

### US-03 Save candidate profile
As a candidate, I want a persistent structured profile so that later jobs can reuse my evidence.

Acceptance criteria:
- Candidate profile data persists across sessions.
- Profile changes do not modify historical tailored resume snapshots.

## Epic: Job Description
### US-04 Add job
As a candidate, I want to paste a job description and optional job metadata.

Acceptance criteria:
- JD is required.
- Company, title, location, URL, salary/CTC are optional.
- Original JD text is preserved.

### US-05 Analyze JD
As a candidate, I want the JD converted into structured requirements.

Acceptance criteria:
- Required and preferred requirements are distinguished where possible.
- Skills, tools, frameworks, responsibilities, qualifications, experience, and soft skills are surfaced.

## Epic: Matching
### US-06 Analyze match
As a candidate, I want my profile compared with the job so I can understand alignment.

Acceptance criteria:
- Results are grouped as matched, weakly represented, missing, and unsupported.
- Each important result can expose supporting evidence.

### US-07 View estimated match
As a candidate, I want an estimated job match metric.

Acceptance criteria:
- Metric is explicitly labeled as an estimate generated by PrivateResume.
- It is not labeled or presented as an employer ATS score.

### US-08 Understand recommendations
As a candidate, I want concise explanations for why a skill or project was selected.

Acceptance criteria:
- Explanations cite candidate evidence and/or job requirements.
- Internal chain-of-thought is not exposed.

## Epic: AI Tailoring
### US-09 Generate tailored resume
As a candidate, I want a tailored draft grounded in my existing evidence.

Acceptance criteria:
- Draft is generated from structured candidate data, JD, and match analysis.
- No unsupported qualifications are introduced.

### US-10 Prevent fabrication
As a candidate, I want unsupported claims explicitly prevented or flagged.

Acceptance criteria:
- Missing skills are not automatically added.
- Unsupported technologies, certifications, metrics, or experience are not invented.

### US-11 Edit generated resume
As a candidate, I want to edit tailored sections manually.

Acceptance criteria:
- Each core section is editable.
- Manual edits can be saved as new versions.

### US-12 Ask AI to modify a section
As a candidate, I want to request a targeted revision.

Acceptance criteria:
- User can specify the target section.
- Candidate can accept, reject, or further edit the result.

## Epic: Generation and Validation
### US-13 Generate LaTeX
As a candidate, I want approved content placed into my template.

### US-14 Generate PDF
As a candidate, I want a compiled PDF preview and downloadable artifact.

### US-15 Validate resume
As a candidate, I want objective checks of the generated file.

Acceptance criteria:
- Checks cover PDF generation, text extractability, required sections, contact details, placeholders, headings, and unsupported claims.

## Epic: Versioning
### US-16 Save resume versions
As a candidate, I want previous drafts to remain identifiable and immutable.

## Epic: Applications
### US-17 Save application
As a candidate, I want to save a job application with the exact resume version used.

### US-18 Update status
As a candidate, I want to track statuses: Saved, Applied, Assessment, Interview, Rejected, Offer, Withdrawn.

### US-19 View history
As a candidate, I want to view the original JD, analysis, submitted resume version, PDF, notes, and timeline.

## Epic: Reliability and Security
### US-20 Handle AI failure
As a candidate, I want useful error handling when Ollama is unavailable or returns invalid data.

### US-21 Protect data
As a candidate, I want authentication and authorization around my resume and profile data.

### US-22 Isolate users
As a candidate, I want assurance that another user's data cannot be accessed through my account.

### US-23 Retain control
As a candidate, I want a clear human approval point before final generation.
